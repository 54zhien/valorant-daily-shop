# 掌上无畏契约（掌瓦）游戏数据 / 商店数据链路分析报告

- **样本**：`com.tencent.apps.valorant.apk`（118 MB，7884 个 entry）
- **版本**：`versionName=2.10.1`，`versionCode=10076`（`AndroidManifest.xml` 解析结果）
- **分析方式**：APK 解包 → 全量 dex 字符串提取 → jadx 全量反编译（59753 个类）→ 资源/清单二进制解析（AXML 手工解析）
- **工具链**：`work/jadxtool/JadxRunner.java`（基于 jadx-headless-mcp 内嵌的 jadx core API），`work/axml_parse.py`，`work/*_scan.py`
- **结论日期**：基于该 APK 快照

> 全部结论都标注了来源（类名 / 文件 / 字符串），可以逐条复核。

---

## 0. 一句话结论

掌瓦**不是**直接连 Riot 的 `pd.*.a.pvp.net`。它走的是腾讯自己的一套 **`/go/*` REST 网关**（生产域名 `app.mval.qq.com`），
用 **QQ / 微信 SSO 换来的票据（ct / wt / ctt）+ openid / access_token / tid** 放进 Cookie 头完成鉴权；
无畏契约的游戏数据（资产、皮肤、对局、以及商店）由这套网关向国服游戏后台取数后返回 JSON。

**但是**：该 APK 快照里**没有编译进「每日商店」页面本身**。商店 UI 属于**服务端下发的 React Native bundle / 动态 UI（plaster）**，
它的**接口路径不在 APK 里**，必须运行时抓包才能拿到。下面第 4、5 节给出了完整抓取方案和替代实现路径。

## 1. 网络层骨架（这部分完全逆向清楚了）

### 1.1 传输栈

| 环节 | 实现 |
|---|---|
| HTTP 客户端 | OkHttp（`okhttp3`，自研封装） |
| 门面 | `com.tencent.base.http.c`（`HttpProtocolUtils`） |
| 统一回调 | `com.tencent.base.http.HttpProtocol.b#onFinished(ErrorCode, ResponseData)` |
| 成功判定 | HTTP 200 / 304 → `Succeeded`，其余 → `ServerError`，异常 → `Timeout` |
| UA | `com.tencent.base.http.d`（`HttpUaCache`）：`{appInfo} {SystemWebViewUA}` |
| 业务协议 | `com.tencent.container.protocol.b`（`BaseProtocol`）+ `com.tencent.container.protocol.a.a`（注解协议） |

**请求体 / 方法规则**（`com/tencent/container/protocol/b.java`, `.../a/a.java`）：

- 注解协议（`@com.tencent.container.protocol.Protocol(path=...)`）：**POST JSON**，body = `getProtocolBody()`，`Content-Type: application/json`。
- `BaseProtocol`：body 非空 → POST JSON；body 为空 → **GET**。
- Cookie 拼装：`com.tencent.base.http.c.a(...)` 把 `List<String[]>` 按 `k=v; k=v; ` 拼成一个 `Cookie` 头。

### 1.2 响应信封（所有 `/go/*` 一致）

```jsonc
{ "result": 0, "msg": "success", "data": { ... } }
```

- `com/tencent/container/protocol/a/a.java#c(String)`：`result != 0` 即失败，`data` 反序列化为协议泛型。
- **`result == 999999` ≠ 业务错误，而是「wt 票据异常」**，需要刷新票据后重试。
  证据：`com/tencent/zone/main/MainZoneHomeActivity.java:1251`
  ```
  "Http协议返回999999，wt票据异常，主动刷新"
  ```
  以及 `com/tencent/mlol/startup/basiclaunch/d.java:345`
  ```

  ```

见 `com/tencent/container/c/b/a.java`）。

### 1.4 游戏区标识：`game_zone`

`AppEnvironment.a(String url, Map params)` / `b(String body, Map params)`：
对**非白名单域名**的请求，自动在 query（GET）或 JSON body（POST）里补：

```
game_zone        = <当前游戏区>       // 无畏契约端游 = "val"，手游/共创 = "codev"
source_game_zone = <上一个游戏区>
```

配套实现 `com/tencent/qt/qtl/activity/k.java`（`ValZoneBodyWrapper`，实现 `com.tencent.base.http.e` 即 `IRequestBodyWrapper`）。

> 这就是「同一套接口如何区分 LOL / 掌瓦」的开关。你的独立 App 调 `/go/agame/*` 时必须带上 `game_zone=val`。

### 1.5 Cookie 注入（**鉴权的核心**）

`com/tencent/container/c/a/a.java`（`CookieHelper`）是固定顺序拼装的，**这是最重要的发现**：

```java
// 恒有
clientType = 9
// accountType(com.tencent.container.app.AppContext.l()) == 5  → QQ 登录
acctype    = "qc"
uin        = "o" + <QQ uin>            // 注意前缀 o
appid      = <openqq_appid>            // 102061775
// accountType == 2 → 微信登录
acctype    = "wx"
appid      = <wx_appid>                // wxcbb49f1f39656c2a
// 恒有
openid        = <openid>
access_token  = <access_token>
// 掌瓦 user_id 非空时
userId        = <user_id>
accountType   = <1|2|5>
// tid 非空时
tid           = <tid>
```

配合 `com/tencent/container/app/AppContext.java`，票据字段来源一目了然：

| Cookie | 来源字段 | 说明 |
|---|---|---|
| `userId` | `AppContext.b` | 掌瓦账号 id（`u-xxx`），由 `/go/auth/*` 下发 |
| `tid` | `AppContext.e` | 掌瓦票据，本地按 `tid_<userId>` 缓存 |
| `openid` | `AppContext.h` | 第三方（QQ/微信）openid |
| `uin` | `AppContext.i` | QQ 号 |
| `access_token` | `AppContext.j` | 第三方 token，带过期时间 `AppContext.k` |
| `accountType` | `AppContext.g` | `authType 0→1`、`1→2`、`4→5`（`a(...)` 里的映射分支） |

`accountType` 白名单：**5 = QQ，2 = 微信**（和 CookieHelper 里的 `if (5 == l())` / `if (2 == l())` 一致）。

另外 `AppEnvironment` 还有一套 **H5/WebView 域名白名单**（`/go/zone/kv_tree?key=legal_hosts` 下发），
默认值就写在包里：

```json
{"hosts":["zt.huya.com",...,"val.qq.com","tencent.com","game.qq.com",...],
 "cookieHosts":["qt.qq.com","lolm.qq.com","vct.qq.com","lole.qq.com","lolriotmall-wx.qq.com",...],
 "secureHosts":["val.qq.com","qt.qq.com","lolm.qq.com","lole.qq.com","lol.qq.com","lpl.qq.com","jcc.qq.com"]}
```

—— `cookieHosts` 决定哪些域名共享登录态给内嵌 H5；`secureHosts` 是必须走安全通道的域名。

### 2.1 商店页的真实入口（修正：之前判定「不在包里」是错的）

先前结论「每日商店不在 APK 里」**只对了一半**。准确的说法是：

- **商店页的容器和它的数据源，在 APK 里，写得死死的**
- **只有「每日商店」那张卡片内部的具体商品，是服务端下发的 RN 渲染的**

证据 `com/tencent/zone/main/ZoneMallHomeFragment.java`（编译自 `classes9.dex`，Kotlin）：

```java
@kotlin.Metadata(... d2 = {"Lcom/tencent/zone/main/ZoneMallHomeFragment;", ..., "app.zonemain.impl_valRelease"})
@com.tencent.base.route.api.RouteInfo("valpage://mobile_store_main")
public final class ZoneMallHomeFragment extends com.tencent.zone.main.ZoneHomeFragment {

    @Override
    protected java.lang.String getDefaultTabSrcUrl() {
        return "/go/zone/v3/channel?zone=shop&disableAlgo=$DISABLEALGO$";
    }
}
```

读法：

| 线索 | 含义 |
|---|---|
| `impl_valRelease` | 这是 **val flavor** 的产物 → 掌上无畏契约自己的类 |
| `@RouteInfo("valpage://mobile_store_main")` | 掌瓦页面路由表里的「商城主页」 |
| `getDefaultTabSrcUrl()` | 该页默认 tab 的**数据源 URL** |
| `zone=shop` | zone channel 框架里的 shop 频道 |

所以**商店接口的第一候选**是：

```
POST https://app.mval.qq.com/go/zone/v3/channel?zone=shop&disableAlgo=0
```

`$DISABLEALGO$` 的取值逻辑在 `com/tencent/qt/module_information/data/d.java`：
`r7 == 0 ? "0" : "1"`，默认给 `0`。

**另一台正式域名**：`com/tencent/qt/module_information/data/c.java:47`

```java
"https://app.val.qq.com/go/zone/v3/channel?zone=$ZONE$&disableAlgo=$DISABLEALGO$"
```

`module_information/data/c.java` 里同一处还有 `mlol.qt.qq.com` 的版本，两者是同一接口的新旧域名。
**`app.val.qq.com` 是之前没发现的域名，探测时要和 `app.mval.qq.com` 一起试。**

同一个 zone channel 家族的其他成员：

```
/go/zone/v3/channel?zone=game_zone&disableAlgo=$DISABLEALGO$&favzone=$FAVZONE$   ← 游戏主页
/go/zone/v2/game_channel
/go/zone/v2/bottomtab?zone=%s
/go/zone/gamelist
/go/zone/views_layout?key=…
/go/zone/kv?key=…
```

**全 APK 里 `/go/` 下唯一带 shop 的路径就这一条**（`all_strings.txt` 全局扫描确认），
其余商店相关字面量只有 `"商城入口"` / `"商城签到卡"` / `"跳转商城失败"` 三个 UI 文案。

### 2.2 为什么没法「直接在自己 App 里登 QQ / 微信」，必须抓包

两个登录协议的真实请求体：

```java
// com/tencent/wglogin/authsuite/protocol/LoginByWXProtocol.java
@Protocol(path = "/go/auth/login_by_wechat")
class Params { int clienttype; int mappid; String mcode; ConfigParams config_params; LoginInfo login_info; }
    class LoginInfo { String appid; String code; int wx_info_type; int check_third_type; }

// com/tencent/wglogin/authsuite/protocol/LoginByQQProtocol.java
@Protocol(path = "/go/auth/login_by_qq")
class Params { int clienttype; int mappid; String mcode; ConfigParams config_params; LoginInfo login_info; }
    class LoginInfo { long appid; String openid; String sig; long uin; int qq_info_type; }
```

三条硬墙：

1. **`openid` 是按 AppID 维度生成的。** 掌瓦服务端记的是「在 AppID `wxcbb49f1f39656c2a`
   （微信）/ `102061775`（QQ）下你的 openid」。你用自己的 AppID 登录，拿到的 openid 完全不同，
   服务端认不出你是哪个账号。
2. **微信会校验拉起方。** iOS 上必须 bundle ID + **Universal Link** 在开放平台注册过，
   用掌瓦的 AppID 去拉，签名对不上微信直接拒绝跳转。
3. **QQ 的 `sig` 需要 AppKey。** 由 `TencentOpenAPI` 内部用 AppKey 算，AppKey 不在 APK 里。

结论：**走一遍真实客户端登录（= 抓一次包）是唯一可行路径。**
但好消息是，抓到的 Cookie 配合 `ct`，配合 2.1 的 `zone=shop`，很可能已经够用了。

### 2.3 票据语义的最终确认（做 iOS 自刷新时必须知道）

**`tid` 就是 `wt`。** 证据是 `com/tencent/wglogin/authsuite/core/a.java:441-455`：

```java
public void a(java.lang.String r2) {          // 参数是 wt
    ...
    r0.e(r2);                                  // core.b.e(wt)
    com.tencent.container.app.AppContext.a(r2); // → AppContext.b(String) → 字段 e
}
```

而 `AppContext.b(String)` 把值存进字段 `e`，并按 `tid_<userId>` 缓存；字段 `e` 正是 Cookie 里的 `tid`。
所以 `/go/auth/get_web_ticket` 拿到的新 `wt` 会直接变成下次请求的 `tid`。

**`ct` 不在 Cookie 里。** `CookieHelper` 只发 `userId / tid / openid / access_token / uin / accountType / clientType`。
`ct` 只在 `/go/auth/get_web_ticket`、`/go/auth/get_client_tmp_ticket`、`/go/auth/refresh_client_ticket`
的 body 里出现——**想自刷新票据，抓包时必须把 ct 一起拿到**（`AppContext.a(...)` 的第 2 个参数）。

**`SsoAuthType` 枚举**（`com/tencent/wglogin/datastruct/SsoAuthType.java`）：

| 名称 | code | Cookie `accountType` |
|---|---|---|
| `WT` | 0 | 1 |
| `WX` | 1 | 2 |
| `OPEN_QQ` | 4 | 5 |
| `TOURIST` | 255 | 1 |

映射逻辑在 `AppContext.a(...)` 尾部：`0→1`、`1→2`、`4→5`、其它 `→1`，
和 `CookieHelper` 里 `if (5 == l())`（QQ，`acctype=qc`，`uin=o<uin>`）/
`if (2 == l())`（微信，`acctype=wx`）完全吻合。

**`/go/auth/refresh_third_token`**（`com/tencent/wglogin/authsuite/protocol/a.java`，是 `BaseProtocol` 所以走 POST）：

```jsonc
// 请求
{"type": 4, "uuid": "<掌瓦 user_id>", "openid": "<openid>"}
// 响应 ThirdTokenResult
{"access_token": "…", "expired": <秒>, "time_interval": <秒>}
```

- `type` = `SsoAuthType.getCode()`
- `uuid` = user_id（`authsuite/core/a.java:497-498` 把 `$UUID$` 占位符也绑成 user_id）

**URL/body 里的占位符**（`com/tencent/container/c/b/a.java`）：
`$APPID$=10001`、`$CLIENT_TYPE$=9`、`$PLAT$=android`、`$PROTO_VERSION$`、`$TIME$`、
`$IPV4_ADDR$`、`$NET_STATUS$`、`$UUID$=<user_id>`。

## 5. 「每日商店」到底在哪？（关键结论 + 抓取方案）

### 5.1 商店确实存在，容器在 APK 里、卡片内容在服务端（详见 §2.1）

**存在的证据**（`res/layout/activity_feature_switches.xml`，编译后的二进制 XML，已解出字符串）：

```
翻牌动画
商店每日首次查看是否使用翻牌动画
卡背隐藏品质
翻牌前的卡背隐藏皮肤的品质
```

对应的开关 key（`com/tencent/switches/protocol/UserSwitch.java:477,487`）：

```java
"val_close_shop_commodity_animation"   // 关闭商店商品动画（翻牌）
"val_hide_shop_commodity_quality"      // 翻转前隐藏卡背上的品质
```

开关页面 `com/tencent/qtl/setting/FeatureSwitchesActivity.java` 在切换时**不动 UI，只往 RN 层发信号**：

```java
Bundle b = new Bundle();
b.putInt("isSet", v);
b.putString("key", UserSwitch.VAL_CLOSE_SHOP_COMMODITY_ANIMATION.getKey());
com.tencent.qt.qtl.rn.b.a().a("receiveBrandSignal", b);   // ← 发给 React Native
```

配套本地资源：`res/drawable-xhdpi-v4/ic_val_goods_quality_1..5.png`（5 档品质角标，usage 见 `com/tencent/mval/e.java`），
分享图 `agame_store_share_bg_default_{land,port}.png`、`agame_store_share_combo_bg_default_land.png`、`agame_store_share_footer_logo{,_dark}.png`。

**结论**：

1. 掌瓦 **有** 商店页面，形态是「翻牌」式的每日商店（4 张卡背 → 逐张翻开 → 显示皮肤 / 品质）。
2. 该页面 **100% 由 RN / 动态 UI（`com.aladdinx.plaster` 引擎）渲染**，native 端只提供品质图标和分享图。
3. 因此**商店接口路径不在 dex / 资源 / 清单里**，只能运行时抓。

### 5.2 抓包方案（推荐顺序）

| 方案 | 难度 | 说明 |
|---|---|---|
| **A. Frida Hook OkHttp** | ★★ | 最稳。直接 hook `okhttp3.Request`，连 Cookie、body、response 一起 dump，不受证书固定影响。脚本：`capture/frida_okhttp_dump.js` |
| **B. mitmproxy + 去证书固定** | ★★★ | 需要 root 或改包。掌瓦有 `network_security_config`（`usesCleartextTraffic=true`），主要固定点在腾讯自家 SDK。addon：`capture/mitm_zhangwa.py` |
| **C. 直接扒 RN bundle** | ★★★★ | bundle 下载后落在 `/data/data/com.tencent.apps.valorant/files/...`，root 后 grep `store`/`穿越` 关键字即可找到接口常量 |

**只要抓一次「打开每日商店」，就能拿到**：

```
POST https://app.mval.qq.com/go/<商店路径>
Cookie: clientType=9; acctype=qc; uin=o<uin>; appid=102061775; openid=<openid>; access_token=<token>; userId=<u_id>; accountType=5; tid=<tid>
Content-Type: application/json
{"game_zone":"val","source_game_zone":"...", ...商店参数（roleId/game_open_id/...）}
```

抓到后填进 `server/zhangwa.py` 的 `SHOP_PATH` 即可。

### 5.3 不想抓包？走官方接口（国际服 / 通用）

无畏契约国际服每日商店是公开契约，所有第三方商店 App 都走这条：

```
1. 本地 Riot Client lockfile（<安装目录>/lockfile）：
     Riot Client:<port>:<password>:https
2. GET https://127.0.0.1:<port>/entitlements/v1/token
     Authorization: Basic cmlvdDp<password 的 base64>
   → { accessToken, token(entitlement), subject(puuid) }
3. GET https://pd.<shard>.a.pvp.net/store/v3/storefront/{puuid}
     X-Riot-Entitlements-JWT: <entitlement>
     Authorization: Bearer <accessToken>
   → { SkinsPanelLayout: { SingleItemOffers[4], SingleItemStoreOffers[...] }, BonusStore(夜市) ... }
4. 皮肤名/图标 → https://valorant-api.com/v1/weapons/skins
```

`shard`：`na` / `eu` / `ap` / `kr` / `latam` / `br`。
国服（腾讯代理）这块目前**没有公开契约**，所以国服方案仍然回到 5.2 的抓包路线。
